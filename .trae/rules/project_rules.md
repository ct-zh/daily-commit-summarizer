# Daily Commit Summarizer Go语言化改造指导

## 项目概述

本项目是一个基于AI的每日Git提交摘要工具，当前使用TypeScript实现，需要改造为Go语言版本。项目的核心功能是：

1. 收集指定时间范围内的Git提交记录
2. 获取提交的diff内容并进行分片处理
3. 调用LLM API生成提交摘要
4. 汇总生成每日开发变更日报
5. 通过Webhook发送通知（如飞书）

## 改造依据文档

**重要：** 请严格参考 项目根目录下的`Go语言实现方案.md` 文档进行改造，该文档包含了完整的Go语言实现架构设计。

## 当前TypeScript实现分析

### 核心功能模块

1. **环境变量配置**
   - OPENAI_API_KEY: LLM API密钥
   - OPENAI_BASE_URL: LLM API地址
   - LARK_WEBHOOK_URL: 飞书Webhook地址
   - MODEL_NAME: 模型名称（默认gpt-4.1-mini）
   - PER_BRANCH_LIMIT: 每分支提交数限制（默认200）
   - DIFF_CHUNK_MAX_CHARS: diff分片最大字符数（默认80000）

2. **Git操作功能**
   - 获取远程分支列表
   - 收集指定时间范围的提交
   - 获取提交diff内容
   - 处理提交元数据（SHA、标题、作者、分支、URL）

3. **Diff处理功能**
   - 文件过滤（排除lock文件、构建产物等）
   - 按文件分割diff
   - 按字符数分片处理

4. **LLM集成功能**
   - OpenAI Chat API调用
   - 提示词模板管理
   - 分片摘要生成
   - 提交级别摘要合并
   - 日报级别汇总

5. **通知功能**
   - 飞书Webhook发送
   - 错误处理和降级

### 8. 开发约束规范

**重要约束：** 当接收到具体的代码编写需求时，大语言模型必须严格遵循以下规范：

- **需求边界限制**：严格限定在用户明确提出的需求范围内完成开发，不得超出需求边界
- **禁止延伸开发**：不得基于文档内容或个人判断进行功能延伸、扩展或额外实现
- **精确实现原则**：只实现用户明确要求的功能点，不添加用户未明确要求的特性
- **避免过度设计**：不得因为"最佳实践"或"完整性考虑"而添加用户未要求的代码
- **需求确认机制**：如对需求范围有疑问，应明确询问用户而非自行扩展

**示例说明：**
- ✅ 正确：用户要求"实现配置模块的环境变量读取功能"，则只实现环境变量读取，不添加配置文件读取
- ❌ 错误：用户要求"实现配置模块的环境变量读取功能"，却同时实现了配置文件读取、配置验证、默认值设置等未明确要求的功能

此规范确保开发过程的可控性和用户需求的精确满足。
